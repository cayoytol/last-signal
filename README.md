# LAST SIGNAL / Последний сигнал

Первая играбельная версия кооперативного экшена: восстановите три модуля станции «Кеплер-09», защитите реактор и эвакуируйте выживших. Доступны одиночная тренировка и WebSocket комнаты до четырёх игроков.

## Запуск игры

Откройте опубликованный проект. «Начать экспедицию» запускает соло. Для кооператива выберите «Создать отряд», укажите имя и роль, затем передайте приглашение или код напарнику. Другой игрок выбирает «Войти по коду». Командир запускает миссию из лобби. Для разных пилотов в одном браузере используйте разные вкладки без дублирования существующей вкладки; обновление вкладки сохраняет её сессию.

Проект по умолчанию публикуется с личным доступом. При игре с коллегами им требуется доступ к самому проекту; код комнаты не обходит настройки доступа. Не публикуйте игру для всех без отдельного решения владельца.

WASD/стрелки — движение, мышь — прицел, ЛКМ — огонь, Space/Shift — рывок, E — удерживать для ремонта/поднятия, R — перезарядка, Q — способность, Escape — настройки. В соло настройки приостанавливают симуляцию; сетевой мир продолжает работать. Для сенсорного экрана предусмотрены джойстик и кнопки с автоматическим выбором ближайшей цели.

## Структура проекта

- `game/engine.ts` — чистая детерминированная симуляция, общая для сервера и соло.
- `game/server.ts` — HTTP создание/вход, аутентификация сессии и обработка WebSocket сообщений.
- `game/network.ts` — клиентский транспорт, повторное подключение и повторные запросы запуска.
- `game/renderer.ts` — Three.js сцена, модели, освещение, эффекты, интерполяция отображения.
- `game/Game.tsx` — управление, меню, интерфейс миссии, настройки и подсказки.
- `game/audio.ts` — синтез звука через Web Audio, без внешних аудиофайлов.
- `db/schema.ts`, `drizzle/` — D1 схема комнат и игроков, миграция.
- `tests/game-engine.test.mjs`, `tests/game-network.test.mjs`, `tests/game-runtime.test.mjs` — проверки игровых правил и двух сетевых сессий.
- `ROADMAP.md` — концепция, выполненный объём и этапы дальнейшей разработки.

## Проверка и сборка

Требуется Node.js 22.13+; для тестов используется встроенный `node:sqlite` (проверено с Node.js 24).

```bash
npm run test:game
npm run typecheck
npm run build
```

Основной проект использует установленный Vinext/React стартер и Cloudflare Worker. `worker/index.ts` обслуживает `/api/rooms` и `/api/socket` до передачи остальных запросов приложению. Миграции D1 применяются публикацией через Sites. Производственные идентификаторы базы и настройки доступа управляются площадкой.

## Сеть и пределы версии

Каждый игрок подключается к `/api/socket?room=CODE`, затем отправляет секретный токен отдельным сообщением авторизации. Токен не передаётся в ссылке приглашения. Игрок отправляет только намерения управления; позиции, столкновения, урон, лечение и итог миссии рассчитывает сервер.

Клиент отправляет ввод примерно 11 раз в секунду. Сервер использует короткие шаги по 1/60 секунды, хранит общую комнату в D1 и записывает результат только при совпадении её предыдущей версии. Это позволяет нескольким Worker экземплярам координировать одну комнату без раздельных миров. После обрыва игрок сохраняет место в отряде; ввод старше 900 мс становится нейтральным, отсутствие связи более 12 секунд помечает игрока отключённым. Место может быть освобождено при новом входе после двух минут отсутствия. Комнаты живут два часа, устаревшие очищаются при создании новых.

Частые запросы к D1 добавляют задержку и стоимость. Такой способ рассчитан на испытания небольшой версии. Для массовой эксплуатации нужен отдельный координатор игровой комнаты (Durable Object либо серверный процесс) и измеренная нагрузка. Сглаживание и ограниченное предсказание движения уже есть, полноценная компенсация сетевой задержки запланирована.

Документация платформы: [Cloudflare WebSocket API](https://developers.cloudflare.com/workers/runtime-apis/websockets/), [координация соединений через Durable Objects](https://developers.cloudflare.com/durable-objects/best-practices/websockets/), [D1 batch API](https://developers.cloudflare.com/d1/worker-api/d1-database/).

## Что проверено

14 автоматических сценариев проверяют ограничения ввода, детерминизм, попадания, отсутствие урона союзникам, столкновения, совместный ремонт, поднятие раненого, эвакуацию всем составом выживших, поражение, восстановление оружия и способности, согласованное состояние двух WebSocket сессий, ограничение комнаты четырьмя местами и отказы при неверной авторизации/источнике.

Основные тесты транспорта используют настоящую SQLite схему и эмуляцию API Worker/WebSocket. Отдельный интеграционный тест запускает настоящий локальный workerd через Miniflare, открывает два WebSocket соединения, запускает общую миссию и проверяет её запись в D1. Это не испытание браузерного рендера, реальных сетевых задержек или производственной площадки под нагрузкой. Визуальное прохождение в браузере и игра с нескольких реальных устройств ещё не выполнены.

Собственные игровые модели создаются кодом в реальном времени, сторонние платные игровые ассеты не используются. Сторонние библиотеки сохраняют свои лицензии. Сохранение игрового прогресса между разными миссиями пока не реализовано; локально запоминаются только настройки устройства и временная сессия вкладки.
